# 学食モバイルオーダー 画面リニューアル 設計書

- 日付: 2026-10-21
- 対象リポジトリ: `yukkuri1224-lisa/gakushoku-order`
- 状態: 承認済み（画面構成・データ・見た目はチャットで確認済み。以降はおまかせの指示あり）

## 目的

今のサイトに残っている「AI っぽさ」をなくし、マクドナルド・サブウェイ・モスの
モバイルオーダーと並べても見劣りしない、本格的なモバイルオーダーの見た目と使い勝手にする。
あわせて、メニューに選択肢（大盛り・福神漬け）を持てるようにする。

## 参考にした調査（REA ＋ ブラウザでの観察）

- サブウェイのウェブ注文（`order.mypicks.fun`）: メニュー → 商品詳細 → 選択肢 → カート追加 → カート（支払い直前まで）
- マクドナルド: ウェブのメニュー・商品ページ（注文はアプリ専用）
- モス: 公式サイトのメニュー・ネット注文の案内ページ（ネット注文サイトは国外からの接続を拒否）

取り入れるのはレイアウトと導線のパターンのみ。他社のロゴ・画像・コードは使わない。

## 決定事項

### 1. 画面の構成と流れ

1. **入口（合言葉）** — 仕組みは今のまま。見た目を整え、タイトルの不自然な改行を直す。
2. **メニュー（/menu）**
   - 上部固定ヘッダー: 店名「LiSA校食堂」＋点数バッジ付きカートアイコン。
   - 受け取り情報の帯:「受取：LiSA校食堂｜できあがったらこの画面でお知らせします」。
   - 横長1列のリスト（左に正方形の写真、右に名前・一行説明・価格）。行全体が1つのボタン。
   - カテゴリ見出し（麺類／ご飯もの）。品数が少ないのでタブは付けない。
   - カートが空でないとき、最下部に固定ボタン「カートを見る・N点・¥合計」→ /checkout へ。
   - 今の下から出るカート（CartSheet）は廃止。
3. **商品詳細（下から開くシート）**
   - 大きな写真、名前、説明、基本価格。
   - 選択肢グループ（どれも「1つ選ぶ」）: サイズ（必須：普通／大盛り +¥150、初期値 普通）、
     カレーのみ福神漬け（つける／つけない、初期値 つける）。
   - 数量 −／＋ と「カートに追加する・¥金額」（選択肢と数量で金額が変わる）。
   - 追加したらシートを閉じ、「カートに追加しました」を短く表示（トースト）。
4. **カート兼注文確認（/checkout）**
   - 受け取り情報 → 選んだ商品（選択肢の内容、数量変更、削除）→ 合計 → 注意事項 → PayPay で支払う。
5. **支払い後**
   - PayPay から戻ったときの確認中画面は見た目のみ整える。
   - 注文番号画面（/order/:id）: 大きな番号、進み具合（受付済み → 調理中 → 完了）、選択肢付きの注文内容。
6. **厨房ボード（/staff）**
   - 選択肢のうち初期値から変えたものだけを強調表示（「大盛り」は太字、「福神漬けなし」は注意色）。

### 2. データの持ち方

```ts
interface OptionChoice { id: string; label: string; priceDelta: number }
interface OptionGroup {
  id: string
  label: string
  required: boolean        // 表示上の「必須」ラベル用。どのグループも必ず1つ選ばれている
  defaultChoiceId: string
  choices: OptionChoice[]
}
interface MenuItem {
  id: string
  name: string
  price: number            // 基本価格
  category: string         // '麺類' | 'ご飯もの' など
  description?: string     // 一行説明
  image?: string
  optionGroups?: OptionGroup[]
}

// 注文・カートの1行
interface SelectedOption {
  groupId: string
  groupLabel: string
  choiceId: string
  choiceLabel: string
  priceDelta: number
  isDefault: boolean       // 初期値のままなら true（厨房では表示しない）
}
interface OrderItem {
  key?: string             // menuItemId + 選択肢の組み合わせ。カートの行の識別子
  menuItemId?: string
  name: string
  price: number            // 選択肢込みの単価（合計計算は従来どおり price × quantity）
  quantity: number
  options?: SelectedOption[]
}
```

- メニュー:
  - 醤油ラーメン ¥430（麺類）— サイズ: 普通 / 大盛り +150
  - カレーライス ¥480（ご飯もの）— サイズ: 普通 / 大盛り +150、福神漬け: つける / つけない
- 同じ商品・同じ選択肢の組み合わせは同じ行（数量が増える）。違う組み合わせは別の行。
- 既存の Firestore の注文（`key` / `options` なし）は「選択肢なし」として表示できる。
  カートの行の識別子は `key ?? name` を使う。
- 合計金額は従来どおりブラウザで計算して PayPay に渡す（デモの範囲として改ざん対策はしない）。

### 3. 見た目のルール

| 役割 | 値 |
|---|---|
| 地の色 | 白 `#FFFFFF`、薄い灰色 `#F5F5F4` |
| 文字・メインボタン | 墨色 `#1C1917`（補助文字 `#57534E`、薄い文字 `#A8A29E`、線 `#E7E5E4`） |
| アクセント（小さなラベルのみ） | 地 `#FDF3D7`、文字 `#7A5300` |
| 注意 | `#B42318` |
| 完了 | `#15803D` |
| PayPay ボタン | `#FF0033`（例外） |

- フォントは端末の標準日本語フォント。太さは normal / bold の2段階のみ（font-black / extrabold は使わない）。
- 文字サイズ: 画面見出し 20px、商品名 16px bold、説明 13px、価格 16px bold（`tabular-nums`）。
- 角丸 8px。影は下から開くシートと最下部の固定バーのみ。カードで囲まず細い線で区切る。
- メインボタンは高さ 52px・横幅いっぱい。押せる要素は 44px 以上。
- 絵文字はやめ、線のアイコン（カート・閉じる・戻る・時計・お店・チェック）をインライン SVG で持つ。
- 動きはシートのスライド（0.25 秒）程度。浮遊・ポップのアニメーションは削除。
  `prefers-reduced-motion` のときは動きを止める。
- 写真は料理部分を正方形に切り抜き、価格の文字と見出しの帯を外す。長辺 800px 程度に縮小。
- 商品行は `<button>`、選択肢は `role="radiogroup"` / `role="radio"` で作る。
- `theme-color` を白に変更。

### 4. エラー時の動き

- **支払い済みなのに注文の登録に失敗した場合**（前回の「Missing or insufficient permissions.」のような失敗）:
  カート画面には戻さず、「お支払いは完了しています。注文の登録に失敗しました」と表示し、
  「注文の登録をやり直す」ボタンで **支払いをやり直さずに** 登録だけを再試行する。
- **注文登録を二重にしない**: PayPay の支払いID（merchantPaymentId）を注文のドキュメントIDに使い、
  採番と注文の書き込みを1つのトランザクションで行う。同じ支払いIDの注文が既にあれば、それを返す。
  これで再試行やページの再読み込みをしても、注文が2件にならない。
- Firestore の権限エラーは英語のまま出さず、日本語で「お店のシステム設定に問題があります。スタッフにお知らせください」と出す。
- 選択肢はすべて初期値を持つため、未選択のまま追加されることはない（未選択エラーは不要）。

## 確認方法

- ロジック（選択肢込みの単価、行の識別子、初期値、旧データの扱い）を Vitest で単体テストする。
- `npm run build`（型チェック ＋ ビルド）が通ること。
- ブラウザ（390px 幅）で各画面をスクリーンショットし、崩れがないことを目で確認する
  （入口・メニュー・商品詳細・カート・注文番号・厨房ボード）。
- モック決済モードで「メニュー → 選択肢を選ぶ → カート → 支払い → 注文番号 → 厨房ボードに選択肢が出る」
  の一連の流れを確認する。

## やらないこと

- 本格的なログイン・会員機能、クーポン、受け取り時間の指定
- メニュー管理画面
- 金額の改ざん対策（サーバー側での再計算）
- Firestore のセキュリティルールの変更
