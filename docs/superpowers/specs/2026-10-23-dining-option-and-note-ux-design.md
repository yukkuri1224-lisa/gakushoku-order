## 取り入れないもの

| 記事のパターン | 理由 |
|---|---|
| 店舗検索・地図・現在地・お気に入り | 店舗が 1 つだけ |
| カテゴリのフィルターチップ | 2 品だけ（品数が増えたら追加する） |
| クレジットカード入力・LINE Pay・クーポンコード | 支払いは PayPay のみ、クーポンはない |
| 下部タブバー・注文履歴画面・アカウント | 会員機能がない。今の注文は「注文中」カードで足りる |
| プッシュ通知（通知パネル） | サーバーと通知許可の仕組みが必要。画面内の通知音・全画面のお知らせで代替 |
| グラデーションの配色、ライト／ダークの 2 テーマ | 前回の「AI っぽさをなくす」方針と合わない。確認の手間が倍になる |
| 受取時間「約 5〜10 分後」、営業時間・ラストオーダー | 根拠となるデータがない（待ちは「前に◯件」で代替） |

## 画面の流れ

```
/ 合言葉（ゲート済みなら /start へ）
→ /start 利用方法の選択（注文中カード）
→ /menu メニュー（利用方法の帯、注文中カード）→ 商品シート
→ /checkout 注文内容の確認（受取場所・利用方法・支払い方法・注文内容・合計）
→ （PayPay）→ 注文を確定しています… → /order/:id 注文番号
/staff 厨房ボード（利用方法のバッジ）
```

- `/menu` と `/checkout` は合言葉が必要。`/menu` は利用方法が未選択なら `/start` へ戻す。
- `/checkout` は利用方法が未選択でも開ける（その場で選べる）。未選択のうちは支払いボタンが押せない。

## データ

- `DiningOption = 'eat_in' | 'takeout'`
  - 表示名: 店内で食べる／お持ち帰り。厨房向けの短い名前: 店内／持ち帰り
- 利用方法の選択は `localStorage`（`gakushoku.dining`）に保存する。PayPay から戻っても消えないように、カートと同じ扱いにする。
- `Order.diningOption?` / `OrderDraft.diningOption?` を追加する。旧データにはないので、ない場合は表示しない。
- 注文ドキュメントは `buildOrderData()` で作り、`undefined` の項目は書かない（Firestore は `undefined` を拒否するため）。
- この端末でした注文を `localStorage`（`gakushoku.myOrders`、`{ id, createdAt }[]`）に記録する。表示するのは今日の注文だけ。
- 「注文中」カードに出すのは、進行中の注文と、できあがってから 30 分以内の注文。
- 「前に◯件」は、進行中（受付済み・調理中）の注文のうち、自分より先に作られた件数。
